本文件延續 WHO-162 的七區定義，補上 WHO-170 尚未完成的兩個輸出：

- Output 2：代理輸出與人工維護的共用規則
- Output 3：日常協作流程範例

---

## 3. 代理輸出與人工維護的共用規則（Output 2）

### 3.1 代理輸出預設落點（不自行新增平行結構）

| 內容類型 | 預設落點 | 禁止行為 |
| --- | --- | --- |
| 正式專案程式碼、可部署成果 | 主場區 | 直接放到筆記區或封存區 |
| 單次任務產出（需求拆解、交付草稿、暫存分析） | 任務區 | 任務未結束就丟入知識母本區 |
| 短期驗證、可拋棄實驗 | 試煉區 | 直接升格為正式專案而無驗證紀錄 |
| 尚未啟動的想法、提案草案 | 孵化區 | 與正式專案混放 |
| 已整理且可重複引用的標準、SOP、規格 | 知識母本區 | 直接存放未整理草稿 |
| 個人反思、判斷脈絡、工作日誌 | 筆記與思考區 | 當成正式規格對外引用 |
| 已結束且近期不再使用的內容 | 封存區 | 長期滯留主場區或任務區 |

### 3.2 人工整理後回寫規則

1. 代理先輸出到「任務區」或「試煉區」。
2. 人工檢查可復用性：
   - 可作為團隊共同規則：回寫到「知識母本區」。
   - 僅供個人脈絡追蹤：回寫到「筆記與思考區」。
3. 回寫時必帶最小追溯資訊：
   - 來源任務編號（例如 WHO-185）
   - 更新日期
   - 狀態（草稿 / 已驗證 / 已封存）
4. 任務關閉後，任務區僅保留必要索引；可刪除中間檔或移至封存區。

### 3.3 交接規則（給其他 AI 或未來自己）

- **先看狀態再看內容**：每份文件開頭需標示「任務編號 + 狀態 + 更新日期」。
- **先找知識母本，再回溯任務區**：需要可執行規則時，以知識母本區為第一來源。
- **草稿不冒充正式規格**：任務區與試煉區內容預設非最終版。
- **接手三步驟**：
  1. 讀任務目標與限制
  2. 讀知識母本區對應條目
  3. 必要時回看任務區 / 試煉區的推導過程

## 4. 日常協作流程範例（Output 3）

### 4.1 單一任務完整流向（接收 → 執行 → 輸出 → 沉澱 → 封存）

以 WHO-185 為例：

1. **接收**
   - 任務建立於任務區，標示目標是補齊 Output 2 / Output 3。
2. **執行**
   - 代理依既有七區規則產生草稿，不另建新命名系統。
3. **輸出**
   - 初稿放任務區，附上任務編號與日期。
4. **沉澱**
   - 人工將可重用規則整理進知識母本區；
   - 將判斷脈絡與反思寫入筆記與思考區。
5. **封存**
   - 任務結束後，中間草稿移入封存區或刪除，只保留必要索引。

### 4.2 可重複遵守的驗證清單（多 AI / 人工共用）

- [ ] 不同 AI 的輸出都先落在既有七區之一，沒有新平行資料夾
- [ ] 任務結束前，至少一次人工回寫到知識母本區或筆記區
- [ ] 接手者能在 5 分鐘內判斷「內容位置」與「狀態」
- [ ] 已完成任務不再長期佔用主場區 / 任務區
- [ ] 需要升級的內容有明確升級條件與記錄
